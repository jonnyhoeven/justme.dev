## Codebase Review (2026-11-12)

Full read of the components, `lib/`, theme CSS, ETL scripts, CI and docs at commit `8139ff1`. Lint (ESLint, Prettier, Ruff) and both test suites pass on that commit. Items marked _(from code)_ were derived by reading the source and have not been checked in a browser. Ordered by impact within each group.

### 1. Bugs

- [ ] **A track that fails to load leaves the player "playing" silence** ([`useMusic.ts`](.vitepress/theme/composables/useMusic.ts) `loadAndPlayTrack` / `switchTrack`): `XMPlayer.loadBuffer` returns `false` on a parse error and `loadUrl` throws on HTTP errors, but the result is ignored and nothing catches the throw. After an auto-advance, `isPlaying` stays `true`, the rAF loop keeps running and the rejection is unhandled. `issues.md` already lists 193 files that may not parse. Catch it, set `isPlaying = false` (or skip to the next track after N failures) and show the error in the title area.
- [ ] **Stale load can win a race** (same function): `currentLoadedUrl` is set after `await xmPlayer.loadUrl(url)`. Skip twice quickly on a slow connection and the older fetch can resolve last, so track A plays while the UI shows track B. Keep a load token (or `AbortController`) and drop results that are no longer current.
- [ ] **Hero tagline is partly unreadable in light mode** _(from code)_ ([`components.css`](.vitepress/theme/components.css) `.VPHero .tagline`): the gradient's middle stop is a fixed `#cbd5e1`, which is about 1.5:1 on a white background. Use a token that flips with the theme (e.g. `--vp-c-text-2`).
- [ ] **Custom blocks lose their type colour** _(from code)_ ([`layout.css`](.vitepress/theme/layout.css) `.custom-block`): `background-color: rgba(255,255,255,.5) !important` overrides the tip/warning/danger backgrounds, so `--vp-custom-block-tip-bg` in `tokens.css` is dead and all callouts look alike. Tint per type instead, e.g. `color-mix(in srgb, var(--vp-custom-block-tip-bg) 60%, transparent)`.
- [ ] **Deep-link example in the tracker post does not work** ([`blog/tracker.md`](blog/tracker.md)): it shows `?track=dead_lock.xm`; the catalog filename is `0_deadlock.xm` and `applyTrackQueryParam` only matches exact filenames.
- [ ] **Hero physics is frame-rate dependent** ([`HeroSplat.vue`](components/HeroSplat.vue) render loop): spring, damping (`* 0.8`), the kick punch and `glowLevel += … * 0.08` are applied per frame, so on a 120 Hz display the cloud is stiffer and settles twice as fast as on 60 Hz. `ctx.dt` already exists; scale forces by `dt / 16.67` and use `Math.pow(damp, dt / 16.67)`.
- [ ] **Phase timers use wall time across pauses** (same file): `phaseStart` and `startTime` are not shifted when the loop stops off-screen, so scrolling back to the hero usually triggers an immediate morph and animations jump. Accumulate active time from `dt` instead.
- [ ] **Progress bar assumes 64-row patterns** ([`xm-player.ts`](lib/audio/xm-player.ts) `getProgress`): patterns can have 1 to 256 rows, so the bar jumps or stalls on such songs. Precompute cumulative row counts per order at load.
- [ ] **ETL failures do not fail the build** ([`process_requests.py`](scripts/process_requests.py)): a failed README fetch or an invalid manifest is logged and the script exits 0, so CI can deploy a project page with an empty body or drop the page. Exit non-zero when any manifest fails (and label YAML/validation/network errors separately; the broad `except Exception` calls them all "Validation error").

### 2. Performance

- [ ] **The 3,405-track catalog is downloaded on every page**: `MiniPlayer` sits in the global layout and `useMusic` statically imports `data/music.data`, so every visit loads about 689 KB of JS (117 KB gzip). `manualChunks` only splits it; it is still eagerly imported. Load it on first play or first playlist open (dynamic `import()`), and ship only the curated `INITIAL_TRACK_FILENAMES` entries up front.
- [ ] **Shrink the catalog itself** ([`data/music-tracks.json`](data/music-tracks.json), [`sync_audio_r2.py`](scripts/sync_audio_r2.py)): every `url` equals `MEDIA_URL + '/audio/' + filename` (0 exceptions) and there are only 49 distinct `tracker` strings. Dropping `url` and using tuples with a tracker lookup table takes it from 689 KB to about 280 KB raw. The 831 KB pretty-printed JSON also churns the git history on every sync.
- [ ] **Mobile LCP waits for hydration; desktop downloads an unused image** ([`HeroSplat.vue`](components/HeroSplat.vue)): the fallback avatar and canvas are toggled with `v-show` from `useWindowSize`, which is `Infinity` during SSR. Phones get `display: none` on the avatar until JS runs, and desktops fetch `ava.webp` for nothing. Switch visibility with CSS media queries, add `width`/`height` and `fetchpriority="high"`, and only start the canvas from JS.
- [ ] **Article hero image is lazy-loaded** ([`ArticleItem.vue`](components/ArticleItem.vue)): it is the LCP element on every post but has `loading="lazy"` and no dimensions. Remove `lazy` there, keep it for list cards below the fold, and add `width`/`height` (images are generated at 653x378) to both to stop layout shift.
- [ ] **653px images are used as 133px thumbnails** ([`ArticleList.vue`](components/ArticleList.vue), [`gen_image.sh`](gen_image.sh)): generate a small variant (e.g. 266px for 2x) and use `srcset`/`sizes`.
- [ ] **Audio is mixed on the main thread** ([`xm-player.ts`](lib/audio/xm-player.ts)): `ScriptProcessorNode` is deprecated and competes with the hero canvas and Vue for the same thread. Port the mixer to an `AudioWorklet` (the engine is already self-contained in `createXMEngine`); send scope/VU data back with `postMessage`.
- [ ] **Allocations inside the audio callback** (same file, around lines 1210 to 1240): a `Float32Array` per channel per tick for `VU` and scopes, plus a fresh `scopes` array. Preallocate per song and reuse; GC pauses here are audible.
- [ ] **Tracker canvases redraw at 60 fps even when nothing changed** ([`TrackerPlayer.vue`](components/TrackerPlayer.vue) `animLoop`): the pattern grid only changes when `curRow`, pattern, mutes, page or width change, and neither canvas changes while paused. Redraw on change, cache `getContext('2d')`, and replace the per-channel `shadowBlur = 8` (expensive with 32 channels) with a cheaper double stroke.
- [ ] **Per-particle garbage in the hero loop** ([`HeroSplat.vue`](components/HeroSplat.vue), `lib/splat-animations/*`): every animation's `apply` returns a new object per particle per frame (560 particles, 60 fps), and tinted scenes build an `"r, g, b"` string plus a `fillStyle` parse per particle. Use an out-parameter like scenes already do, and quantise tint colours into a small cached palette.
- [ ] **Non-compositor background animation** ([`components.css`](.vitepress/theme/components.css) `.articleImagebg`): `glow` animates `background-position` forever under a `blur()` filter, forcing a repaint of a blurred layer every frame on every article. Animate `transform` on an oversized pseudo-element, or make it static.
- [ ] **`.vp-doc > div > *` entrance animation** (same file): every top-level block of every page starts at `opacity: 0` and keeps `transform` from `animation-fill-mode: both` (a stacking context per block). Limit it to the first screen or drop it; it delays first paint of text.
- [ ] **Third-party badge requests** ([`Badges.vue`](components/Badges.vue), footer in [`config.mts`](.vitepress/config.mts)): each project card loads three `img.shields.io` images and the footer two more on every page. Fetch star/fork counts in the ETL and render them as local badges.
- [ ] **Hero canvas ignores `devicePixelRatio`**: it is sized in CSS pixels, so it is soft on HiDPI screens. Try `min(dpr, 2)` backing size and measure the frame cost before keeping it.
